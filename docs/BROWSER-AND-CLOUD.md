# 浏览器对照 · 云端工作区（2026-11-21，待主人定）

## 一、浏览器：各家怎么做

| App | 浏览器在哪 | 亮点 |
|---|---|---|
| Open Minis 1.16（手机上做得最好） | App 内，旅伴后台操作 | 多标签，随时接手；网页 / 图片 / 文档能缩成浮动圆球，点开展开、下拉关；下载有进度卡和下载面板；能打印；可走 Tailscale / 代理；可改视口 |
| DSH Go | 不是 App 自己的：靠手机里装的 Linux 或远端电脑上的 DSH | 浏览器能力跟着它连的那台机器走 |

## Clio 现在有的

一个旅伴和主人共用的真浏览器（登录跨启动保留）；读页面时把可点的东西编号；点、填、滚、截图、后退；从信匣填密码（不进日志）；电脑版切换；下载存进书案；每轮第一次去某个网站要主人点头；需要主人动手时交回来；聊天页上有实时小窗。

## 差距（按价值）

1. **浮动预览**：回复里的链接、图片、文档先浮在聊天上，缩成小圆球，不整页跳走（Minis）。
2. **多标签**：旅伴能同时开几页对比；主人随时接手，接手时旅伴停下等。
3. **下载面板**：下载进度和下过的文件在一处看。
4. **读页更省**：长页面先抽正文（像阅读模式），不够再要编号元素；截图只在需要时给。
5. **走代理 / Tailscale**：要等网络设置一起做。
6. **存成 PDF / 打印**。
7. **手机锁屏后浏览器会被系统停掉**：本机解决不了，见下面「云端浏览器」。

## 二、云端：手机只是个壳

主人的意思：书案、斗室（终端）、浏览器都放在一台云服务器上，手机只负责聊和看。参考 DSH Go：它能通过 SSH 连电脑或服务器上的 DSH，手机只做界面。

可以做，分三步，越往后越大：

- **第一步（11-21 查过：Clio 已经有了）**：「远山」里加主机（SSH，钥匙登录），对话的「在哪干活」选这台主机，书案的读写和终端命令就都在服务器上；长任务用后台任务（ssh_job_start / check / stop），断线、锁屏照样跑。原计划写的是：**连一台自己的服务器（SSH）**。在设置里加「云端书案」：填服务器地址，用钥匙登录（钥匙放信匣）。之后旅伴的终端命令在服务器上跑，书案读写服务器上的文件；模型还是从手机直接调用。手机锁了，正在跑的命令在服务器上照样跑完（用 tmux 之类挂着）。工作量：中。
- **第二步：云端浏览器**。服务器上跑一个无头 Chromium，旅伴操作它，手机上看截图或实时画面。锁屏也不停，登录状态留在服务器。工作量：中到大。
- **第三步：整个旅伴搬上云**。服务器上跑一个常驻小程序，模型调用、记忆、定时任务都在那边，手机关了也一直在干活；手机打开时同步进度。等于再写一个服务端。工作量：大。

要注意：服务器要主人自己准备（之前在看的香港 VPS 就可以）；连接用钥匙不用密码；服务器上的东西不进 Clio 的备份；不做账号体系。

## 等主人定

- 云端先做第一步，还是直接到第二步。
- 云端和本机的书案 / 斗室并存（每个对话选在哪干活），还是整体切过去。
