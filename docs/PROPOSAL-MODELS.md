## 一、现状走查：第一次用的人一路会看到什么

按真实使用顺序走一遍当前 `batch-0.34` 的 7 个触点：

### 1. 首次添加服务（`SetupView`）
- 选服务商（15 项竖列）→（如多区域）选国内/海外 →（如自定义或豆包）填称呼/地址/模型名 → 填密钥 → 自动拉列表并预选最多 12 个（或建议集/前 3 个）→ 点「接上」→ 到「接好了」完成页。
- **卡壳点**：
  - 知名服务如果拉模型列表失败，提示语写着「也可以直接填模型名」，但因为不是自定义服务，**手填模型名的输入框根本没显示**，用户卡死在原地。
  - 首次接入只调了 `provider.models()`，没拉 `OpenAIProvider.catalog()` 里的上下文窗口，要等以后进服务页手动点「刷新模型列表」才拿得到。

### 2. 设置首页的「模型」组（`SettingsView`）
目前平铺了 3 个入口：
1. **模型服务**（管理已接服务、添加新服务）
2. **默认和备用模型**（选择聊天、备用和记忆整理模型）
3. **生图模型**（选择 AI 画图用的模型）

### 3. 点进「模型服务」（`SettingsView.destination(.services)`）
- 上面是已接服务列表 + 底部的「添加服务」；
- 下面又放了一张大卡片（`overview`），展示**当前默认模型**和余额，点这张卡片却跳进了「默认模型所在的服务商页」，既不是换默认模型，也不是看模型能力。

### 4. 点进某一家服务（`ServicePage`）
从上到下塞了 5 块：
1. 顶栏 3 个按钮：`试连`、`刷新模型列表`、`管理密钥`
2. **在用的模型**（点一行弹 `ModelSheet`；长按弹「设为默认模型 / 移除模型」；卡片最底塞着「手动添一个模型名」）
3. **列表里还有 N 个**（搜索 + 点 `+` 启用）
4. **接口**（称呼、地址、区域切换、**思考参数格式**、密钥）
5. **余额** + 底部红色「删除此服务」

### 5. 点一个模型弹出的详情（`ModelSheet`）
用的是系统 `Form` 样式（和设置其他页视觉不统一），分 3 组：
1. **模型能力**：看图、用工具、思考开关 + `上下文` 档位。说明仍写着「按名字猜的，服务不会告诉我们」（实际上已经接了 `models.dev` 和接口返回的窗口）。**这里完全看不到已探测出来的思考档位（`traits.levels`），也无法单独改或清。**
2. **测试**：`全面测一下（看图、工具、思考）`、`测试看图`、`测试连接`。底部说明写着「发一张红色小图问颜色，花一点点钱」——其实「全面测一下」最多会连发 **8 次** API 请求（连通用 + 看图 + 工具 + 5 个思考档位）。
3. **角色与清理**：`设为默认模型`、`按模型名称恢复默认`、`移除模型`。

### 6. 点进「默认和备用模型」与「生图模型」
- **默认和备用模型**：标题只说「默认和备用」，里面其实装了 **3 个角色**（默认模型、备用模型、记忆整理模型）。前两个是自绘 `paperField` 按钮，第三个是 `RowCard` + `RowLabel(end: .none)`（**连下拉箭头都没有**，看着像不能点）。
- **生图模型**（`ImageModelPage`）：另起了一个系统 `Form` 页，自己带一套「选择服务 + 手填模型名 + 刷新模型列表」，和 `ServicePage` 的模型管理各管各的。

### 7. 聊天页切换模型和思考档位（`ChatPage`）
- **平时看不见**：`modelChip` 只在输入态（`composing == true`）才出现，不打字时完全不知道当前用什么模型、开没开思考。
- **思考档位藏在二级菜单里**：单聊里只有一个 22pt 小图标，点开菜单 → 再点「思考：默认」子菜单才能选档位；群聊又单独露了一个思考图标，两套交互不统一。
- **文案与逻辑打架**：对不能关思考的服务（如 Kimi），菜单已经隐藏了「不想」，底部说明却还写着「不想会按浅想来」；对 Claude 即使模型不会思考也给全 6 档。

## 二、问题汇总：为什么会觉得「又杂又乱，逻辑不对」

核心原因是把 **4 件不同层级的事** 拆碎并重复塞进了 6 个页面里：

| 层级 | 本质是什么 | 现状哪里乱 |
|---|---|---|
| **1. 服务商（连接）** | 账号、密钥、地址、协议、余额、思考参数格式 | 入口在「模型服务」，但「生图模型」又自己刷新一次列表；「模型服务」底下硬塞了默认模型卡片 |
| **2. 模型清单（启用）** | 从服务商挑哪些模型放进常用池、手填模型名 | 添模型分散在 `SetupView`、`ServicePage`、`ImageModelPage` 三处，刷新逻辑还不一致 |
| **3. 模型能力（属性）** | 看图、工具、思考开关、上下文、实测思考档位 | 藏在 `ServicePage` 点击后的 `ModelSheet`，聊天页和角色分配页完全看不到入口；测出来的 `levels` 看不到也调不了 |
| **4. 角色分配（用途）** | 聊天默认、出错备用、记忆/日记整理、生图、单旅伴指定、单对话临时切换 | 设「默认模型」有 **4 个入口**；4 个全局角色被硬拆成「默认和备用模型」（装了 3 个）+「生图模型」（单独 1 页且样式不同）；删服务商时甚至漏清 `backupModel` |

## 三、外部参考对比（批判地看，只学适合 Clio 的）

| 产品 / 项目 | 它们怎么组织「服务商 → 模型 → 能力/思考 → 默认模型」 | 值得 Clio 学的 | 不适合 Clio 的（不要照抄） |
|---|---|---|---|
| **Cherry Studio** | 左侧「模型服务」管所有服务商（填密钥 + 勾选启用模型 + 模型分组/能力图标）；独立「默认模型」一页集中选：默认助手模型、话题命名模型、翻译模型、生图模型。聊天底栏直接并排选模型和推理强度。 | **把「服务商和模型池」与「默认用途分配」彻底拆成清晰的两块**；所有用途（聊天/备用/记忆/生图）在一页收齐，不拆散。 | 桌面端多栏和成百上千个细碎开关太重，手机端不需要每个模型单独配温度/top_p/频率惩罚。 |
| **ChatGPT / Claude App** | 顶部标题下直接显示当前模型名（一眼可见），点一下切换；思考开关/档位在输入框栏直接一键切换，不藏在二级菜单里。 | **聊天页把「当前模型」和「思考档位」放到一眼可见、一步可点**，零学习成本。 | 它们只有自家几款模型，不需要管理多服务商密钥与自定义端点。 |
| **HanaAgent**（Apache-2.0，可借鉴写法并致谢） | 手机端个人助手，把模型服务配置与「默认用途」解耦，首次引导极简（只管先接通能聊，进阶参数后置）。 | 首次接入只抓「接通 + 挑几个常用」，把思考协议格式、能力覆写收进「高级 / 探测」，不吓跑新用户。 | 无需照搬其多端同步与桌面配置结构。 |
| **Open Minis**（GPL，只学思路不抄代码） | 「模型库」视角：先连服务商启用模型，再按场景指定；能力标签用小胶囊直接展示在模型名旁，测通后自动落标签。 | 启用模型后在各处都能直观看到能力胶囊，减少来回翻页确认。 | 不照抄其 UI 组件与配色，保持 Clio 纸墨与 `Kit` 组件体系。 |

## 四、建议的新结构（干净的三层模型）

把 4 个概念收拢成 **2 个设置入口 + 1 套统一的聊天快捷切换**，让用户一眼懂「**先接服务商选好模型 → 再给各个用途指派模型 → 聊天时随手换**」：

### 设置首页「模型」组（从 3 行精简为 2 行）

```text
模型
┌──────────────────────────────────────────┐
│ [图标] 模型服务          已接 3 家 · 12 个模型  › │  ← 管连接、密钥、启用模型、模型能力
├──────────────────────────────────────────┤
│ [图标] 默认用途          聊天、备用、记忆、生图  › │  ← 一页管齐全部 4 个全局角色
└──────────────────────────────────────────┘
```

*(注：原来「模型服务」和「默认和备用模型」「生图模型」三行合成清晰的两行；书卷模式下「模型服务」继续叫「笔庄」，「默认用途」可定名如「各司其职」或保持日常「默认用途」——见第五节待拍板。)*

---

### 页面 1：`模型服务`（原 `Services` 列表页）

去掉底部让人困惑的「默认模型大卡片」，本页**只管服务商连接**：

```text
< 设置                 模型服务                 +
┌──────────────────────────────────────────┐
│ [图标] DeepSeek     api.deepseek.com · 2 个  › │
├──────────────────────────────────────────┤
│ [图标] OpenRouter   openrouter.ai · 6 个     › │
├──────────────────────────────────────────┤
│ [图标] Claude       api.anthropic.com · 4 个 › │
└──────────────────────────────────────────┘
                  [ + 添加模型服务 ]
```

- 点某一家进 **`服务商详情`（`ServicePage` 重整）**，按使用频率排成清晰的 3 组：
  1. **常用模型（已启用）**：只列已勾选的常用模型 + 能力胶囊；点一行进 **`模型详情`（`ModelSheet`）**；底部 `+ 管理 / 添模型` 打开统一选模型抽屉（把「从列表勾选」「搜索」「手填模型名」合在一个干净的页里，不再在主页面里长出一大截「列表里还有 180 个」把连接设置挤到最底）。
  2. **连接与密钥**：称呼、地址（含国内/海外切换）、密钥、余额、`测试连接` + `刷新模型列表`（统一调 `catalog()`，同时更新聊天与生图列表及上下文窗口）。
  3. **高级（默认折叠）**：接口类型只读提示 + **思考参数格式**（仅 OpenAI 兼容接口显示，附带一行直接写出「当前会提供哪些思考档位」）。底部红色「删除此服务」（删除时同步清理 `defaultModel` / `backupModel` / `memoryModel` / `imageModel`）。

- **不再在 `ModelSheet` 和 `ServicePage` 长按菜单里塞「设为默认模型」**（或仅在 `ModelSheet` 底部保留一个「去默认用途中指定」提示），避免 4 处入口打架。

### 页面 2：`默认用途`（合并原「默认和备用模型」+「生图模型」）

一页用统一的 `paperCard()` + `RowLabel`（带右侧当前值与展开箭头）把全部 4 个全局角色收齐：

```text
< 设置                 默认用途
  对话与容错
┌──────────────────────────────────────────┐
│ [图标] 默认聊天模型          claude-sonnet-4-6  › │

├──────────────────────────────────────────┤

│       主模型报错或超时时自动接手               │
└──────────────────────────────────────────┘
  后台与生图
┌──────────────────────────────────────────┐
│ [图标] 记忆与日记整理                  跟默认走  › │
│       夜间整理记忆和写日记，可选更便宜的小模型   │
├──────────────────────────────────────────┤

└──────────────────────────────────────────┘
```

- 选**聊天 / 备用 / 记忆**模型时，弹出统一的模型选择页（按服务商分组，只列各家「已启用」的模型，带能力胶囊；同时顶部有「去管理模型服务」快捷跳转）。
- 选**生图模型**时，点进精简后的选图模型页（不再重复做「刷新列表」，直接复用已接 OpenAI 兼容服务的列表 + 手填输入框）。
- 旅伴编辑器（`BotEditor`）里的「专属模型」保持现状（`跟默认走` 或指定一个常用模型），清晰落在「单助手覆盖」这一层。

### 页面 3：聊天页切换模型与思考档位（`ChatPage`）

解决「平时看不见、思考藏太深」的问题：

1. **当前模型一眼可见**：聊天顶栏旅伴名下方（或输入框上方工具条）在空闲时也能淡雅显示当前模型简称（如 `sonnet-4-6`），不抢戏但心里有底。
2. **模型与思考平级、一步直达**：输入框底栏里，**模型按钮**只管选模型（`跟着助手走` + 各服务常用模型），旁边当模型支持思考时直接放一个独立的 **思考档位图标按钮**（像群聊那样，点一下直接选档位，不再藏进二级子菜单）。
3. **顺手修掉两处逻辑毛病**：
   - 不能关思考的服务既然菜单里不给「不想」，就不再显示「不想会按浅想来」的矛盾提示；
   - Claude 不会思考的旧模型（`traits.thinks == false`）不再硬给 6 档思考。

---

### 首次添加服务（`SetupView`）顺手修的 2 个体验坑

1. 任何服务商只要自动拉列表失败，**立刻展开「手动填模型名」输入框**，不再出现「文字叫你填、界面没框填」的死胡同。
2. 首次接入 OpenAI 兼容服务时统一调用 `catalog()`，第一次就能带上上下文窗口和能力信息。

## 五、要删、要合、要挪清单

| 动作 | 对象 | 说明 |
|---|---|---|
| **合** | `默认和备用模型` + `生图模型` → **`默认用途`** | 4 个全局角色（默认聊天、备用、记忆整理、生图）一页收齐，视觉统一为 `paperCard()` |
| **删** | `模型服务` 页底部的 `overview` 默认模型大卡片 | 职责错位（点它进的是服务商而不是换模型），挪回「默认用途」 |
| **删** | `ModelSheet` 里重复的「测试看图」单独按钮（并入「全面探测」+「只测连通性」）与「设为默认模型」 | 减少入口重复，避免和「默认用途」打架 |
| **挪** | `ServicePage` 里的「列表里还有 N 个」+「手填模型名」→ 抽屉页 `管理模型` | 让服务商详情页清爽，连接/密钥/余额不用滑过上百个模型才能看到 |
| **挪** | `ServicePage` 里的「思考参数格式」→ 折叠进「高级」区 | 平时自动猜对不用看，需要排错再展开 |
| **挪** | `ChatPage` 单聊的「思考档位」从模型二级子菜单 → 独立一级按钮 | 和群聊统一，常用高频操作一步到位 |
| **补** | `ModelSheet` 展示已探测的 `traits.levels`；`removeEndpoint` 顺手清理 `backupModel`；`SetupView` 拉列表失败时露出手填框 | 补齐目前隐藏的数据断层与边界 Bug |

## 六、需要主人拍板的 4 个决定

1. **设置里两行的命名**：
   - 日常模式：`模型服务` + `默认用途`（还是叫 `默认模型` / `各用途模型`？）
   - 书卷模式：`笔庄` + 第二行保持日常 `默认用途` 还是另起一个书卷名？
2. **设默认模型的快捷方式**：
   - 是彻底只在「默认用途」一页里改（最干净），还是保留在服务商页长按模型「设为默认」的快捷菜单？
3. **聊天页是否常驻显示模型名**：
   - 在聊天顶栏状态行里平时淡字标出当前模型（如 `deepseek-chat`），还是只在点开输入框时显示？
4. **单聊底栏思考按钮**：
   - 拆成和模型平级的独立思考小按钮（一步切档位），会不会觉得底栏按钮多了一个？（如果觉得挤，也可以放在模型弹出菜单顶部做横向胶囊档位，不进二级子菜单。）
