# 聊天页「舒服丝滑」改造说明（0.34）

主人的要求：聊天要舒服、丝滑。参考 Open Minis 聊天页的做法（**只学思路，不抄代码**，见 `AGENTS.md`）。

## 现在为什么不够顺（诊断）

| 现象 | 原因（代码里的样子） |
|---|---|
| 回复冒字时越写越卡 | `ChatModel.step()` 每 16 毫秒放出几个字，`streaming` 一变，`ProseView` 就把**整段回复从头解析、重新排版**一遍。回复越长每次越重：写到后面就是一秒 60 次重排几千字。 |
| 冒字时页面一顿一顿往下挪 | 每次内容变高，`onScrollGeometryChange` 都立刻发一次「滚到底」，和上面每秒 60 次的重排叠在一起。 |
| 发消息时页面先往上蹿再落回 | 输入框收起（变矮）和新消息出现是两次独立的排版，中间有一帧位置不对。 |
| 往回翻长对话偶尔一跳 | 列表是普通 `VStack`，只画最近 60 条；翻到「更早的」时补画一大批，高度一下子变了。 |

已经有、不用重做的：卡顿记录（「关照」页，`Hitches`）、忙时发的消息排队成虚线气泡且能撤回、做完的步骤收成一行。

## 改完以后你会感觉到的

1. 回复不管多长，冒字都一样顺，不会越写越卡。
2. 停在底部时，页面平稳地跟着新字往下走；你往上翻着看，它不会把你拽回去。
3. 点发送，消息稳稳落在输入框让出来的位置，不跳。
4. 往上翻很长的对话不跳、不卡。
5. 一键回到你上一句话（长回复时找自己刚问的问题）。
6. 做事过程中，连续的工具调用只占一行「正在做第 N 步」，不刷屏。
7. 对话里能搜索，搜到的地方高亮。
8. 长按回复能自由选中其中任意几个字复制。

## 分三批做

### 第一批：手感地基（Claude 做，1～4）

- **A. 冒字分段排版。** 已经写完的段落（遇到空行就算完）排一次版就固定下来，记住排好的结果；只有正在写的最后一段跟着新字重排。放字的节奏不变（仍然顺滑），但画面刷新合并成每秒约 15 次。
- **B. 平稳跟随。** 内容变高时不立刻滚，攒到下一次画面刷新时最多滚一次；「是否贴底」的判断只看你自己的手指（现在的规则保留），新字永远不会抢走你的位置。
- **C. 发送不跳。** 发送时先记下输入框要让出的高度，新消息出现的同一帧里把这段高度补上，两件事合成一次排版。
- **D. 长对话不跳。** 每条消息排好的版面按「内容 + 字号 + 屏宽」记住，往回翻直接用；「更早的」改成快到顶时自动、分小批补上，补的时候保持你眼前那条不动。
- **E. 规则写成纯逻辑 + 测试**（Codex）：分段规则（什么算写完一段，代码块、表格、列表里的空行不算）、跟随规则、发送补位，各自单独测试。

### C14 规则测试

- `python3 tools/test_chat_flow.py` 直接从聊天源码读取现有规则，在独立 Swift 测试夹具里运行。测试替换等待时钟和界面输入输出，保留实际任务取消逻辑。脚本接入 CI。如果布局或方法签名改变，需同步更新提取位置。
- 覆盖普通段落和代码块、手指滚动暂停和恢复跟随、取消过期请求、发送清空编辑态以及和新消息共用一次滚动排队。
- 已知缺口是列表和表格在内部遇到空行会提前定稿。测试报告这两处已知行为，并检查切分没有退化到其他位置。源码当前靠合并滚动维持发送位置，缺少独立的输入框高度补位可供测试。
- 此轮按主人确认避开 `ChatPage.swift`、`ProseView.swift` 和宠物目录。补齐上述规则后可以改成直接调用纯逻辑的测试。真机滚动、动画和卡顿仍按下面的流程实测。
