# Clio 2.0 设置分类树重组方案（Deliverable #6）

> **方法论**：先逐行审计现状 [SettingsView.swift](../../../App/Sources/SettingsView.swift) 真实的 **6 组 / 21 行**，再批判性审视任务书第十一节给出的 **9 组候选树**，最终落地一套**零混杂、Push 一致、可渐进披露、支持中英别名直达**的新设置分类树。

## 一、现状 6 组 vs 候选 9 组批判性对比

| 审视维度 | 现状 6 组 (`SettingsView.swift`) 真实问题 | 第十一节候选 9 组方案评估 | DS 2.0 优化取舍 |
|---|---|---|---|
| **导航一致性** | **极不一致**：21 行里 12 行 push、9 行弹 `.sheet`（连同组内上下行跳法都不同）。 | 需明确统一交互模式。 | **硬规则：全部分类页与详情页一律 `NavigationStack` 右推 (`push`)！** 仅「新建服务向导 / 创建编辑器 / 确认表单」允许 `.sheet`。 |
| **功能藏匿** | `Memory`（需 4 步）、`Vault 密码匣`（藏在面容锁下）、`Voice 语音`（藏在对话显示里）、`Image 生图`（藏在默认模型里）。 | 候选树将 4 者全部提亮出来，方向极正确。 | 在首页卡片和搜索里全部一线可见；同时区分**「规则设置（留设置）」vs「日常内容管理（在侧栏 L1，设置提供快捷跳转）」**。 |
| **`CarePage` 臃肿** | 1,583 行代码把备份、WebDAV、归档、存储、网络探测、掉帧、UIKit 实验、关于全塞进「隐私 › 养护」。 | 候选树把第 8 组「数据与养护」和第 9 组「关于 Clio」分开。 | **坚决拆解 `CarePage`**：拆为「备份与云同步」「存储与归档」「用量与费用」「诊断与性能」四个轻量子页；「关于 Clio」既可单列轻量第 9 组，也可做为设置底部署名区/独立入口，**绝不和隐私混放**。 |
| **分组数量控制** | 6 组看起来短，但每组内部塞满暗门。 | 9 组非常清晰，但要注意第 7 组（通知与后台）若只有 2–3 个轻量开关是否会过度切碎，以及第 1 组「模型与服务」内部 10 个词条不能写成 10 行首页菜单。 | 采用 **清晰 8+1 结构**：首页主列表展示 **8 个核心分组 + 顶部/底部轻量「关于与诊断」区**，严格控制每页层级不超过 3 级，首页每行附带**实时当前状态摘要 + 准确人话说明**（避免无意义空话）。 |

## 三、设置首页列表设计与搜索增强铁律

1. **首页行实时摘要（Value Preview）**：每一行在 `RowLabel` 右侧都要带真实有效摘要（例如：`服务商 → 3 家已连接`、`外观与阅读 → 书卷 · 17pt · 1.65×`、`权限与隐私 → 平衡 · 已锁面容`、`备份与 WebDAV → 昨日 23:10 已加密同步`），用户扫一眼首页就能判断是否需要点进去。
2. **中英+双称谓+别名模糊搜索引擎**：扩展现状 `SettingsPage.keywords`，确保以下查询 **0 失误直达目标页** 并标明所属分组面包屑：
   - 搜 `"ssh"` / `"vps"` / `"服务器"` / `"远山"` → 命中 **远程主机与 SSH**
   - 搜 `"行距"` / `"字体"` / `"spacing"` / `"font"` / `"clreq"` → 命中 **字号、间距与密度 / 字体**
   - 搜 `"记忆"` / `"拾遗"` / `"memory"` / `"忘掉"` → 同时显示 **记忆策略设置**（设置内）与 **打开四层记忆管理**（L1 跳转）
   - 搜 `"语音"` / `"whisper"` / `"stt"` / `"麦克风"` → 直接命中 **语音、听写与朗读**
   - 搜 `"密码"` / `"vault"` / `"token"` / `"信匣"` → 直接命中 **密码匣 (`SecretsPage`)**
   - 搜 `"备份"` / `"webdav"` / `"恢复"` / `"care"` → 直接命中 **备份与云同步**
3. **跨分组双向快捷胶囊**：在「记忆策略设置页」顶部放「管理全部记忆条目 →」，在「记忆管理页」右上放齿轮直跳「记忆整理策略」；在「工具与扩展 › 远程主机」与「工具 › 终端」之间互相直达。

## 四、设置主页视觉纪律、减噪精修与二级 Push 交互规范（v11 最终收敛）

> 消除早期把设置首页做成「仪表盘 + 营销条 + 抢眼艳色徽章墙」的视觉噪声，严格对齐 iOS 设置、Things 3 与 Raycast 的冷静列表秩序：

1. **轻量双身份卡片 (`Slim Dual-Identity Header Card`)**：
   - 仅并排展示 **当前助手名帖** 与 **我的身份**（紧凑内距，点击各自直开编辑，AX3 大字下自动竖排）；
   - **移除原首页 3 枚状态健康胶囊条**：模型连线、面容锁、备份状态**已精确呈现在下方对应行右侧等宽摘要上**，不在页头二次堆砌仪表盘胶囊条。
2. **克制清爽的 8+1 分组列表秩序与视觉减噪**：
   - **收敛微柔和彩色矢量徽章**：图标背板降饱和至文人雅调（黛蓝 `#3B5875`、灰藤 `#5E547A`、暖墨 `#5A5650`、胭脂褐 `#8F524B`、麦褐 `#8E6A34`、松绿 `#336349`），避免整页高饱和彩色格子抢走文字优先级；
   - **清理冗余副标题与行内拥挤**：绝大多数列表行保持 **`单行标题 + 右侧极简状态摘要 + 细箭头`**；仅在涉及密钥、SSH/终端聚合入口或安全承诺的行保留 1 行简洁说明；
   - **统一渐进披露边界**：`模型推理参数`、`Agent 执行策略`、`更多版式细调` 与 `开发者诊断工具 (FrameMeter / 动效实验)` 一律默认折叠，平时不与普通用户日常开关争夺焦点。
3. **中文输入法兼容的 Push 检索与二级页 (`IME-Safe Search`)**：
   - 设置首页搜索栏支持 **日常称谓 + 书卷称谓 + 英文词 + 别名**（同时标明所属分组面包屑并直达 Push）；
   - **拼音输入法保护（P2）**：监听 `compositionstart` / `compositionend` 状态，且输入过滤时**只局部更新结果容器 DOM（绝不重建 `<input>` 节点或 SwiftUI 高频销毁焦点视图）**，确保中文候选词上屏全程零打断；
   - 全部 8+1 分组二级页统一 `NavigationStack` 右推进入，顶栏固定 `‹ 设置` + 居中标题 + 必要操作钮（还原默认 / `＋`）。
