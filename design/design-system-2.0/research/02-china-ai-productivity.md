## 1. 豆包 (Doubao)

- **产品定位与分级**：消费级多模态对话与实时语音 AI 助手（字节跳动）。**分级：`📐 业内设计参考`**（无官方设计大奖核验记录）。
- **证据来源清单**：
  - `[App Store 官方截图/预览]` `[公开交互演示/评测]` 豆包 iOS 客户端功能更新说明与雷锋网/科技媒体对其端到端语音低延迟、插话打断与卡片流体验评测。
  - `[待真机实录补全]` iOS 实机声波球帧率与实时语音打断时的 Taptic Feedback 波形。
- **完整端到端操作流程分析**：
  1. **冷启动与双态输入**：打开直接停在对话页，底部「按住说话 / 键入」与右侧「电话通话」入口明确；支持一键直接切入全屏语音通话态。
  2. **语音通话与打断（Barge-in）**：进入通话态后界面清空文字干扰，中央出现动态声波球；用户说话瞬间可随时插话，AI 立即停止播报并响应新问题。
  3. **多模态卡片输出**：回到文字对话时，搜索天气、日程、英语练口语等均以圆角小卡片嵌入对话流，点击卡片可展开或执行。
  4. **纠错与退出**：语音识别错字可长按修改文本重发；左滑或顶部收起通话浮窗回到主列表。
- **12 维度逐项拆解**：
  1. **中文排版**：字号偏大、段落轻短、口语化分点居多，针对碎片化移动端扫视优化，但严肃长技术文档阅读的层次感偏弱。
  2. **信息密度**：单条气泡密度低、卡片间留白充裕；但功能入口（智能体广场/发现流）逐渐增多后首页略显拥挤。
  3. **布局对齐**：标准主副对话气泡 + 居中声波球 + 底部固定输入胶囊。
  4. **视觉层级**：高饱和品牌蓝点缀核心行动按钮，卡片背景浅灰微区分。
  5. **设计一致性**：消费级友好、圆润亲和，但在「效率工具」与「泛娱乐智能体」之间偶有风格拉扯。
  6. **原生交互**：深度利用全屏语音模态与按住说话滑移取消手势。
  7. **微动效**：声波球随音高与情绪呼吸形变，反应极快。
  8. **触觉反馈**：按下说话、滑至「取消发送」红色区域、切入通话均有清晰反馈 `[公开交互演示/评测]` `[待真机实录补全]`。
  9. **动画打断**：语音 Barge-in 打断响应处于行业最前梯队；但嘈杂环境下偶有底噪误触发打断。
  10. **跟手性**：卡片上下滑动顺畅，但部分可横滑卡片与边缘右滑返回手势偶尔存在轻微方向冲突。
  11. **无障碍**：纯语音链路对视障用户天然友好，但花哨的智能体发现广场信息降噪不够。
  12. **性能与 120Hz 开销**：语音态轻量化视图渲染极快，文字卡片流较平稳。
- **Clio 落地三段论**：
  - **值得借鉴什么**：①**低延迟「打断即响应」交互心智**：用户无需等 AI 写完/说完，可随时自然插话或改写指令；②**按住说话向上滑移取消的清晰物理热区与触觉阈值**；③**结构化生活卡片**（把天气、日程结果变成直观小卡而非纯文本）。
  - **不应该照搬什么**：**坚决不能照搬**大厂消费级 App 的「智能体广场推荐流」「强情感推销」与高饱和泛娱乐氛围，这会毁掉 Clio 安静克制的个人工作台边界。
  - **如何应用到 Clio**：直接优化 `Voice.swift`（语音听写/朗读打断与滑移取消手感）、`Weather.swift` / `HealthCardRows.swift` 等原生工具产物卡片的信息精炼度。

## 2. Kimi

- **产品定位与分级**：主打超长文本解析、搜索溯源与深度研读的生产力 AI 助手（月之暗面）。**分级：`📐 业内设计参考`**（无官方设计大奖核验记录）。
- **证据来源清单**：
  - `[实测视觉核验]` Kimi 官网 `https://www.kimi.com/`（实测加载）：观摩深炭灰工作台（`~#171717` / `#262626` 输入框）、双层复合输入区（上方主框含 `+` / 语音 / 发送，下方附挂 `选择项目` / `插件` 辅槽）与「灵感库」多列圆角模板墙；长文档溯源 Bottom Sheet 与手机行内 `[1]` 热区痛点结合 `[公开交互演示/评测]` 核验。
  - `[待真机实录补全]` 几十万字上下文解析完毕返回首帧渲染时延。
- **完整端到端操作流程分析**：
  1. **上传与长文本挂载**：在输入框附件区一次性传入多份几十万字 PDF/财报，输入框上方出现紧凑的文件胶囊队列与解析状态指示。
  2. **结构化导读与阅读**：首轮回复自动给出长文本分章节摘要和大纲结构，辅助手机用户定位重点。
  3. **行内角标溯源**：回答句末嵌入 `[1]`、`[2]` 可点击角标；轻触后底部弹出 Bottom Sheet 原文卡片并高亮对应引用段，无需离开对话流。
  4. **思考与多轮纠错**：复杂问题默认折叠「思考中/深度思考」状态条；追问时可直接针对前一回复延续或上传补充文件。
- **12 维度逐项拆解**：
  1. **中文排版**：严肃长文排版基准较高，粗体提炼重点、多级标题明确、表格与引用清晰。
  2. **信息密度**：偏高密度生产力风格，适合研读但不至于密不透风。
  3. **布局对齐**：左对齐通栏式 AI 回复最大化利用手机宽度（Clio 早已采用此正确布局！）。
  4. **视觉层级**：正文墨色 > 引用角标/来源底卡 > 折叠态思考块，主次清楚。
  5. **设计一致性**：克制冷静的工具理性美学，极少无意义装饰。
  6. **原生交互**：Bottom Sheet 弹出查来源不丢失当前滚动锚点，符合单手习惯。
  7. **微动效**：文档解析胶囊进度平滑、思考条折展温和。
  8. **触觉反馈**：克制基础点按，复制和切换以视觉微反馈为主 `[待真机实录补全]`。
  9. **动画打断**：底部引用 Sheet 可随时手势下滑关掉；生成长文时支持主动停止按钮。
  10. **跟手性**：长对话滚动较好，但长篇输出时缺乏快速目录跳转或小地图常显入口（这点 Clio 的 `OutlineSheet` + `ChatMinimapOverlay` 已经走在前面！）。
  11. **无障碍**：行内超小上标 `[1]` 点击热区偏窄（容易误触相邻文字，且对指尖粗大或运动障碍用户极不友好）。
  12. **性能与 120Hz 开销**：长篇 Markdown 增量解析在流式结束瞬间偶有轻微布局跳动。
- **Clio 落地三段论**：
  - **值得借鉴什么**：①**Bottom Sheet 原位核验来源（不跳离当前对话）**；②**附件上传后的紧凑文件胶囊列与解析态反馈**；③**严肃研报级中文重点加粗与结构分层**。
  - **不应该照搬什么**：**坚决不能做极小的行内数字上标热区 `[1]`**——手机触屏上必须保证最小触控热区或使用 Clio 现有的 `SourcesRow` 胶囊/行末清晰来源芯片，避免误触！
  - **如何应用到 Clio**：升级 `ChatSources.swift`（`SourcesSheet` 里直接附带网页摘要片段高亮，而不只是域名+链接，点击后用本地隔离预览或半屏查看）、`ChatPage+Attachments.swift` 的多文件队列预览。

## 3. Manus

- **产品定位与分级**：通用自主 AI Agent 与云端沙箱调度工作台。**分级：`📐 业内设计参考`**（无官方设计大奖核验记录）。
- **证据来源清单**：
  - `[实测视觉核验]` Manus 官网 `https://manus.im/`（实测加载，网页端工作台入口）：直观观摩暖白纸感画布（`#f8f8f7`）、中文衬线大标题（`"我能为你做什么？"`）配极细边框大圆角输入框（`20px` 圆角，左下 `+`、右下圆向上箭头）及 6 颗轻量快捷标签胶囊；移动端未在官网首页展示实机画面，多步时间线与人机接管流程结合 `[公开交互演示/评测]` 核验。
  - `[公开交互演示/评测]` 36氪、SegmentFault、CSDN 对 Manus Replay、`todo.md` 规划与 Human-in-the-loop 接管流的拆解。
  - `[待真机实录补全]` iOS 小屏下沙箱终端与浏览器多步回放拖动流畅度。
- **完整端到端操作流程分析**：
  1. **目标下达与自动拆解**：用户输入复杂目标后，界面不急于吐出长文本结论，而是先显性生成一份结构化 `todo.md` 计划步骤列表。
  2. **透明化沙箱执行与步进回放**：任务执行期间，主视图切换为「实时步骤流 + 产物预览窗口」，能看见 Agent 正在操作浏览器、运行 Shell、修改哪份文件；顶部或侧栏有 `View all files` 聚合所有产物。
  3. **人机接管（Human-in-the-loop）**：遇到登录、CAPTCHA、支付或关键决策点，Agent 自动挂起至 `Waiting for User` 状态并高亮提示人工接管，用户处理完点 `Resume` 无缝续跑。
  4. **回放与纠错**：随时拖动时间进度回溯任何中间状态、查看或下载任意阶段生成的文件。
- **12 维度逐项拆解**：
  1. **中文排版**：步骤列表动词短语凝练，文件产物名与状态徽章多用等宽字或清晰标签隔离。
  2. **信息密度**：极高（桌面分栏天生优势）；在手机窄屏下若直接硬塞双栏会极度拥挤，必须通过「顶部规划抽屉 + 对话流折叠步骤 + 全屏预览页」分层收纳。
  3. **布局对齐**：时间线竖轴 + 图标节点 + 工具卡严格左对齐。
  4. **视觉层级**：当前激活步骤（脉冲点/高亮边）> 已完成步骤（弱化对勾）> 未开始步骤。
  5. **设计一致性**：全系统围绕「透明可控的数字劳动力调度台」构建，信任感建立于过程透明。
  6. **原生交互**：产物卡片可点击独立放大查看，人机接管入口优先级最高。
  7. **微动效**：任务完成划勾、步骤状态顺次流转、预览图切换平稳。
  8. **触觉反馈**：桌面起家产品，移动端触觉精细度仍待补齐 `[待真机实录补全]`。
  9. **动画打断**：支持运行中暂停、人工接管并恢复续跑，打破了传统单向黑盒等待。
  10. **跟手性**：移动端回放进度滑块与卡片切换仍有桌面移植感，不如纯原生 iOS 手感顺滑。
  11. **无障碍**：复杂的实时状态流与沙箱画面若无结构化语音摘要，VoiceOver 用户难以跟上。
  12. **性能与 120Hz 开销**：若在列表内直接嵌入实时网页/终端渲染极易掉帧（**这正是 Clio 用 `InteractivePreview.swift` 静态缩略图 + 点击全屏离线 WKWebView、以及 `ChatTrace` 折叠行保持 120Hz 的高明之处！**）。
- **Clio 落地三段论**：
  - **值得借鉴什么**：①**过程透明建立信任**：让用户随时看到 `PlanCard` 与 `ChatTrace` 的真实步骤和产物集合（`All files` 聚合）；②**明确的「暂停等待用户接管」状态机**（对应 Clio 的 `Roam` 浏览器接管 + `InlineApproval` / `ApproveView` + `InlineAsk`）；③**任务结束后的「接着做 / 产物一览」闭环**。
  - **不应该照搬什么**：**坚决不能把桌面端左右双栏「活沙箱监控窗口」硬塞进手机对话列表里**！在 iPhone 上那会抢占滑动手势并让 120Hz 掉帧；也不要无节制在主界面平铺数百行原始终端日志。
  - **如何应用到 Clio**：在 `ChatTrace.swift`、`PlanCard.swift` 和 `Glance.swift` 中整合更清晰的「本轮产出汇总入口」；强化 `ChatPage+Dock.swift` 里「浏览器人工接管 / 强制批准」状态卡的视觉一致性与一键恢复。

## 4. DeepSeek

- **产品定位与分级**：高推理密度对话助手（深度求索 DeepSeek-R1/V3 官方客户端）。**分级：`📐 业内设计参考`**（无官方设计大奖核验记录）。
- **证据来源清单**：
  - `[实测视觉核验]` DeepSeek 官网 `https://www.deepseek.com/`（实测加载）：验证淡蓝白极浅方格渐变底、皇家蓝 `#3b6ff5` 品牌点缀与输入框左下内嵌开关胶囊（`深度思考` / `智能搜索`）；iOS 端思维链左竖线与「已深度思考 XX 秒」折叠行为结合 `[公开交互演示/评测]` 核验。
  - `[待真机实录补全]` 高频流式吐字叠加公式/代码增量刷新时的真机帧率采样。
- **完整端到端操作流程分析**：
  1. **进入与模式切换**：干净单列对话框，底部输入区紧贴「深度思考 (R1) / 联网搜索」两个开关胶囊，切换即改高亮状态。
  2. **流式深度思考**：发出问题后，上方先展开一条「正在深度思考」区域流式吐出思维链；完成思考后可折叠为「已深度思考 XX 秒」摘要头，下方无缝接力输出正式答案。
  3. **长文本/代码/公式消费**：正式答案内数学公式由原生引擎精准排版，代码块以独立横滑卡片呈现并自带右上角「复制 ✓」即时切换。
  4. **防推走与中断**：流式期间用户往上滑看历史时暂停自动滚屏，不强行抢夺视口；底部保留清晰停止按钮。
- **12 维度逐项拆解**：
  1. **中文排版**：极简清晰，以标准苹果系统字体为主，标题与列表对比清楚，理科公式与正文基线对齐扎实。
  2. **信息密度**：默认折叠冗长思维链后，最终结论视窗密度恰到好处，没有多余卡片装饰。
  3. **布局对齐**：思维链左侧竖线引导（2px 细线缩进），严格区分「内心独白」与「正式作答」。
  4. **视觉层级**：灰字思维链+左竖线（低权重）< 墨黑正文与独立代码块（高权重）。
  5. **设计一致性**：极度克制的极客工具风格，功能不多不少，界面极干净。
  6. **原生交互**：代码块独立横向滑动、顶部状态与停止切换自然。
  7. **微动效**：深度思考计时微脉动、复制图标变成对勾的瞬态切换干净利落。
  8. **触觉反馈**：复制代码和开关切换给轻量触发 `[待真机实录补全]`。
  9. **动画打断**：用户手动向上滑即刻打断自动跟底；点开/收起思考块随时响应。
  10. **跟手性**：整体流畅，唯极长公式与大表格快速滑动时需做好缓存预估（Clio 的 PR #91–#93 已实现公式非阻塞估算 + CoreText 异步瓦片）。
  11. **无障碍**：思维链折叠状态、公式替代朗读文本与代码复制按钮标签需明确。

  2. **结构化分块呈现**：返回不再是一串长文字，而是分栏对比卡、步骤时间轴、底端快捷操作按钮（一键加入日程/转长图/存网盘）。
  3. **文件工作台交互**：打开 PDF/文档支持划取一段或表格直接呼出悬浮工具条「总结/解释/翻译」。
- **12 维度逐项拆解**：
  1. **中文排版**：高亮关键词胶囊与分块卡片把长答案切短，适合手机快速扫读。
  2. **信息密度**：卡片内信息密度极高，利用折叠面板隐藏次要细节。
  3. **布局对齐**：模块化卡片对齐工整，但模块种类多时整页纵向视觉略碎。
  4. **视觉层级**：结构化结论卡 > 步骤清单 > 底部操作按钮。
  5. **设计一致性**：近年从极简浏览器向全能超级工作台膨胀，导致内部不同业务卡片样式出现一定割裂。
  6. **原生交互**：划词悬浮栏直接触发上下文动作，路径短。
  7. **微动效**：卡片展开与扫描识别波纹直观。
  8. **触觉反馈**：拍照与按键基础触觉 `[待真机实录补全]`。
  9. **动画打断**：底部弹窗与预览卡支持下拉退出。
  10. **跟手性**：常规卡片流顺滑，大 PDF 工作台依赖原生渲染优化。
  11. **无障碍**：高度结构化表格卡片需要为 VoiceOver 做好单元格行列标题关联。
  12. **性能与 120Hz 开销**：高密度复杂卡片流需严控卡片内嵌套视图数量。
- **Clio 落地三段论**：
  - **值得借鉴什么**：①**把长段文字变成「步骤流 / 对比表 / 可执行底部按钮」的结构化思维**；②**文件阅读器里「划词即问 / 引用追问」**，完美贴合 Clio 刚做的自由选字引用功能。
  - **不应该照搬什么**：超级 App 式的业务膨胀与广告/服务导流入口。
  - **如何应用到 Clio**：深化 `ChatRichTextView.swift` 和 `StudyPage.swift` 文档查看器的「选字 → 引用追问 / 存笔记 / 朗读」统一操作栏，严控文件卡片种类数量以防视觉碎裂。
